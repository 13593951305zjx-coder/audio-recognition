# Android 原生组件与本机数据库设计

手机端承担录音、文件导入、播放、记录管理和结果展示；电脑端服务承担语音转写、文本整理与音高计算。Java 页面调用 `AppRepository`，由仓库管理本机 SQLite 与 HTTP 请求，后台工作完成后回到主线程更新页面。以下字段按 `data/RecordDatabase.java` 的建表语句整理。

## Android 组件映射

| 功能 | 原生组件或实现 | 数据流与作用 |
| --- | --- | --- |
| 九个独立页面 | `Activity`、`Intent` | 欢迎、首页、录音、导入、结果、历史、统计、设置、关于；公共基类不计入页面 |
| 欢迎动画和统计绘制 | `ValueAnimator`、`View`、`Canvas`、`Paint` | 欢迎页波形动画及本机统计的二维图形 |
| 麦克风录音 | `MediaRecorder`、运行时 `RECORD_AUDIO` 权限 | 权限通过后录制并保存手机文件，取消授权时显示提示 |
| 音视频导入 | 系统文件选择器、`ContentResolver` | 从用户选中的内容 URI 读取媒体，复制到应用文件目录供后续访问 |
| 本机播放 | `MediaPlayer` | 播放已录制或已导入且仍存在的本机媒体 |
| 本机记录 | `SQLiteOpenHelper`、`SQLiteDatabase` | 保存本机文件引用、任务状态、完整结果和收藏信息 |
| 服务地址配置 | `SharedPreferences` | 保存用户确认的 HTTP/HTTPS 服务地址 |
| 远程分析 | `HttpURLConnection`、JSON、后台执行器 | 上传媒体，检查服务、读取任务状态、同步服务历史 |

课程要求的原生知识点是列举项至少使用一个；录音/播放已是可验收方向。是否实际通过应由真机或模拟器测试记录证明，不因代码出现 API 名称自动判定。

## 本机数据实体

数据库文件为 `audio_insight_mobile.db`，版本为 1。`records` 是识别记录实体；一条记录保存一份媒体路径及一次远程任务的关联。媒体内容以文件方式保存，识别和分析结果以完整 JSON 文本保存。当前本机模型只有一个实体，没有外键关系，不虚构用户、登录或其他表。

| 字段 | SQLite 类型 | 主键 | 空值/默认值 | 含义 |
| --- | --- | --- | --- | --- |
| `id` | INTEGER | 是，自增 | SQLite 自动分配 | 手机本机记录标识 |
| `task_id` | TEXT | 否 | NOT NULL，默认空串 | 服务端任务标识；草稿尚无任务标识 |
| `title` | TEXT | 否 | NOT NULL | 用户可编辑的记录标题 |
| `file_name` | TEXT | 否 | NOT NULL | 原始或录制媒体名称 |
| `file_path` | TEXT | 否 | NOT NULL，默认空串 | 手机本机媒体文件路径；纯远程同步记录可能暂无本机文件 |
| `server_url` | TEXT | 否 | NOT NULL，默认空串 | 记录关联的服务地址，区分不同服务上的任务 |
| `status` | TEXT | 否 | NOT NULL | 草稿、上传、排队、识别、部分完成、完成、失败等状态 |
| `message` | TEXT | 否 | NOT NULL，默认空串 | 用户可读的进度或失败说明 |
| `result_json` | TEXT | 否 | NOT NULL，默认 `{}` | 完整服务端结果，含转写、摘要或声音分析等实际返回内容 |
| `duration` | REAL | 否 | NOT NULL，默认 0 | 媒体时长，单位秒；未知时为 0 |
| `created_at` | INTEGER | 否 | NOT NULL | 本机记录创建时间，Unix 毫秒时间戳 |
| `favorite` | INTEGER | 否 | NOT NULL，默认 0 | 是否收藏，0 为否、1 为是 |

索引 `idx_record_time` 按 `created_at DESC` 排序；条件唯一索引 `idx_remote_task` 约束非空 `task_id` 的 `(server_url, task_id)`，防止同一服务任务重复同步。标题、文件名和缓存 JSON 支持关键词查询；用户输入通过参数绑定传入 SQLite。

本机操作包括创建、读取、关键词查询、收藏筛选、重命名、更新状态和删除。后续如增加表或字段，应编写保留既有记录的数据库升级迁移。

## 与电脑服务的接口边界

| HTTP 接口 | 手机端用途 |
| --- | --- |
| `GET /api/health` | 检查设置的服务是否可连接 |
| `POST /api/recognition` | 以 multipart 表单上传媒体并建立任务 |
| `GET /api/recognition/status?taskId=...` | 查询真实任务进度、状态和分析结果 |
| `GET /api/recognition/history` | 读取服务历史并同步到本机记录 |

手机仅在用户提交后把媒体传到所配置的服务。电脑需要运行原有 Python 服务以及所选模型。USB 调试场景可以使用 `adb reverse tcp:8000 tcp:8000` 连接电脑端 8000 端口；同一局域网场景使用电脑局域网地址。端口改变时转发命令与设置地址应一致。

本机数据库可保存离线媒体和已取得的结果。断网后新的 AI 识别不能完成；保留本机媒体及已有结果，并向用户说明连接问题，是该场景的验收重点。服务端是否落库、历史是否在服务重启后保留，应在电脑服务侧独立检查；本机记录表本身不证明服务端持久化。
